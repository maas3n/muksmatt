# muKsMaTT v0.1.0-beta.1 — community testing guide

**Experimental prerelease.** Please preserve original discs and backups, and do not use a beta-produced MKV as the only copy. These instructions apply only to the **officially published** `v0.1.0-beta.1` GitHub Release; development rehearsal packages are not substitutes for the beta.

## Get a verified build

1. Use the official [muKsMaTT Releases page](https://github.com/maas3n/muksmatt/releases) and select **v0.1.0-beta.1** once available. Verify GitHub labels it **Pre-release**.
2. Download a package suitable for your system and its corresponding SHA-256 entry in `SHA256SUMS.txt`. A checksum copied from a `0.0.0-dev.*` rehearsal is **not** valid for the beta.
3. Windows: choose Setup, All-in-One, or Portable. Linux x86-64: choose Debian `.deb`, tarball or Standalone (mark the Standalone executable with `chmod +x`).
4. Android/ChromeOS: install the universal, signed `muKsMaTT-0.1.0-beta.1-Android.apk` where sideloading is supported. It is **not** a Google Play release; Chromebooks require Android app support.
5. Note your OS version, architecture, exact package filename, and any installation warning. Run only media you are allowed to access.

Windows PowerShell checksum example:

```powershell
Get-FileHash -Algorithm SHA256 .\muKsMaTT-0.1.0-beta.1-Windows-All-in-One.exe
```

Linux checksum example:

```bash
sha256sum muKsMaTT-0.1.0-beta.1-Linux-amd64Standalone
```

Compare the entire 64-character output to the corresponding entry in the release's `SHA256SUMS.txt` before installing.

## Test matrix

| Source or operation | Windows | Linux | Android / ChromeOS |
|---|---|---|---|
| DVD `VIDEO_TS` folder or DVD ISO | Test remux/demux, tracks, chapters | Test remux/demux, tracks, chapters | Test through SAF; report provider/device |
| Blu-ray `BDMV` folder | **Priority:** native scan, select, remux | **Priority:** native scan, select, remux | Experimental: SAF ISO/BDMV remux |
| Blu-ray ISO file | **Priority:** native scan, select, remux | **Priority:** native scan, select, remux | Experimental: SAF ISO remux |
| Real Blu-ray optical drive | **High priority; unverified** | **High priority; unverified** | USB optical drive unverified/not claimed supported |
| AACS/BD+ protected media | Not validated | Not validated | Not validated |
| Chapters, subtitle/audio selection, LPCM → FLAC | Test using authorized sources | Test using authorized sources | Test supported native remux paths |

**Important distinction:** Successful build and emulator tests cover self-authored, unencrypted media. They do **not** prove that real discs, all commercial playlist layouts, physical drives or decryption work.

## Test steps

### A. Startup and basic UI

1. Install/open the matching package and open each tab.
2. Test scanning a known-good DVD folder or ISO.
3. Select and deselect streams, then perform a short remux and, separately, a demux.
4. Check that the progress display updates, cancellation behaves, and a failed/cancelled run does not overwrite existing files.
5. Record any warnings, missing UI options, failures, or inconsistencies.

### B. Blu-ray folders and ISO (highest priority)

1. Use a legally accessible unencrypted Blu-ray disc/backup or an ISO you created from your own test material. Where possible, compare both the **BDMV folder** and **ISO** form of the same source.
2. Record source form, playlist ID(s), approximate duration, video codec, audio codec, subtitles, number of streams and chapters.
3. Use the Blu-ray scan facility and select one available playlist. Keep all streams for a baseline run.
4. Remux to a **new** MKV on a writable location with sufficient free space. Open it in a media player. Compare beginning, middle, and end; if applicable, check clip/playlist transition points for A/V sync.
5. Repeat with a video-only selection, then an audio-only selection. Check chapter presence and audio-language/track selection.
6. Where LPCM is present, note the input bit depth/channel layout and confirm the output is FLAC; report any change in channel mapping or audio quality.
7. If available, attach sanitized `ffprobe` metadata and a screenshot showing the playlist or error. Never attach copyrighted stream data.

Desktop CLI examples (replace `SOURCE`, and use `muksmatt-cli.exe` on Windows):

```text
muksmatt-cli bluray scan SOURCE
muksmatt-cli bluray remux --output VALIDATION.mkv SOURCE
ffprobe -v error -show_entries stream=index,codec_type,codec_name,channels,sample_rate -show_chapters -of json VALIDATION.mkv
```

Only add `--playlist 00800` if playlist `00800` actually appears in your scan result. The desktop FFmpeg `bluray:` path may reject titles shorter than 180 seconds; see [issue #20](https://github.com/maas3n/muksmatt/issues/20).

### C. Real optical-drive volunteers

Real drives on **Windows/Linux** are the most valuable missing evidence. Record the drive's make/model, USB versus internal connection, OS, media type, whether the app detected the disc, and whether scan/remux worked. Try an unencrypted disc first.

If a disc is protected, only describe its protection type when known and whether scanning/access was supported or blocked. **Do not** share keys or request instructions to circumvent protection; respect local laws. Bundled libraries are not proof that AACS/BD+ protection is handled.

On Android/ChromeOS, external USB Blu-ray drive support has **not been validated or claimed**. A detection/permission report can be useful, but a failure there is not evidence of a supported capability regressing.

## Report an issue or success

Open [a GitHub issue](https://github.com/maas3n/muksmatt/issues/new) and use a title such as `[v0.1.0-beta.1] Windows 11 / external BD drive / ISO remux`.

Copy and fill in this template:

```text
Version/package: v0.1.0-beta.1 / ...
OS/architecture: ...
Drive model/connection (if used): ...
Source: DVD folder / DVD ISO / Blu-ray BDMV / Blu-ray ISO / physical disc
Encryption status (if known): unencrypted / AACS / BD+ / unknown
Provider (Android/ChromeOS): ...
Playlist/length/streams/chapters: ...
What I selected and expected: ...
What happened instead / success result: ...
MKV playback / A/V sync / chapter / subtitle result: ...
Reproduction steps: ...
Sanitized log/error text: ...
```

**Never upload** full discs, copyrighted video/audio samples, decryption material, private paths, device IDs, Android signing keys/certificates, passwords, or personally identifying information. Use only your own legally accessible test media. A positive report is as useful as a failure report.

## Scope of beta qualification

Passing authored-media CI plus successful volunteer tests increases confidence, but the first beta remains **experimental** until real-drive and real-disc coverage has been gathered. Track each result by OS, source class, drive and codec rather than declaring every platform supported from one test. Technical criteria are in [the real-media validation checklist](../BLURAY_REAL_MEDIA_VALIDATION.md).
